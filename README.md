# 运费入仓抽检（Freight Warehouse Sampling）

一张运单关联 **过磅单** 与 **价目** 两张来源表后，可能漏计（某侧命中 0 条）
也可能冒出多条计费明细（某侧命中多条，两次内连接产生笛卡尔积）。服务分两层：

1. **入仓预演层**：用 FastAPI + SQLite 维护每票命中数、每月内连接总行数和
   异常清单，预演阶段不展开计费行。
2. **抽检版层**：审核员入仓抽检只拿到计费行号，需要按发车月开“抽检版”，
   凭版号用行号反查组成该行的三张单据（运单号、过磅记录号、价目记录号）。
   版一旦开成功，行号与三单号的对应关系即被冻结，来源之后补录、更正、撤回
   或服务重启都不改变它。

## 匹配规则

| 来源 | 记录号 | 匹配键 | 操作 |
| --- | --- | --- | --- |
| 过磅单 `weigh_records` | `record_no` 唯一 | 车次 `train_no` | 补录 / 替换 / 撤回 |
| 价目 `price_records` | `record_no` 唯一 | 始发站 `origin` + 发车日落入 `[valid_from, valid_to]`（**含首尾两日**） | 补录 / 替换 / 撤回 |
| 运单 `waybills` | `waybill_no` 唯一 | 车次、始发站、发车日 | `/docs` 一次批量导入 |

- 每票运单的两次内连接生成行数 = `过磅命中数 × 价目命中数`。
- 任一侧命中数 ≠ 1 即异常（0 = 漏配，>1 = 重复），异常页给出两侧各自命中数。
- 月合计按发车月（`YYYY-MM`）统计全部运单的内连接总行数。

## 抽检版怎么工作

### 开版：`POST /samples/months/{departure_mon}/versions`

在**单个 `BEGIN IMMEDIATE` 事务**内、从**同一个已提交状态**冻结以下内容：

| 冻结表 | 内容 |
| --- | --- |
| `sample_versions` | 版头：版号、发车月、总行数、开版时的来源版本号、时间 |
| `sample_waybill_stats` | 该月每票的两侧命中数、本票行数、按运单号升序的累计行数 `cum_rows` |
| `sample_waybill_weigh` / `sample_waybill_price` | 开版当时两次内连接**实际命中**的票↔来源成员关系 |
| `sample_weigh_records` / `sample_price_records` | 去重后的来源记录内容（版内每条来源记录最多一份） |

- 返回**版号与总行数**；每月只保留一个 `active` 版（部分唯一索引兜底）。
- 开版期间写者在锁上等待，期间仍可补录、更正和撤回；开版读到的是等待前
  已提交的状态。
- **开版失败整体回滚，旧版原样保留；成功后同事务删除旧版（外键级联清理），
  只留新版。** 新版本完成前，上一成功版始终可查。

### 行号反查：`POST /samples/versions/{version_id}/lines`

- 请求体 `{"line_nos": [...]}`，**最多 20 个**正整数、不可重复；行号从 1 起算，
  越界返回 422 并列出越界行号。
- 全月两次内连接的结果按 **运单号 → 过磅记录号 → 价目记录号依次升序**编号：
  票间按运单号排序，票内按过磅号、价目号排序（价目为内层）。
- 定位方式：`cum_rows >= 行号` 的第一票（索引点查，**每个行号只读 1 条票
  统计，远优于 32 票上限**），再用票内偏移在冻结成员关系里取过磅/价目记录号。
- **全程只生成抽中的计费行**：命中的行才写入 `sampled_billing_lines`
  （主键 = 版号+行号），重复查询幂等、不重复生成。
- 解析只读冻结表，**不回来源表**：来源改动、服务重启后仍按成功开版时的
  匹配查行（有更正/撤回/重启实测）。

## 接口一览（均在 /docs 可见可调）

### 来源与预演

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/waybills/import` | 批量导入运单；批次内/库内撞号整批 409 回滚 |
| PUT | `/weigh/records/{record_no}` | 过磅单补录或替换（upsert） |
| DELETE | `/weigh/records/{record_no}` | 撤回过磅单，不存在返回 404 |
| PUT | `/price/records/{record_no}` | 价目补录或替换（含窗口倒置校验） |
| DELETE | `/price/records/{record_no}` | 撤还价目 |
| GET | `/rehearsal/months/{mon}/total` | 月内连接总行数（读预聚合表） |
| GET | `/rehearsal/anomalies` | 异常运单键集分页（`cursor`/`limit`，可按月过滤） |
| GET | `/rehearsal/months/{mon}/overview` | 同一只读快照返回月合计 + 异常页 + 版本号 |
| GET | `/rehearsal/waybills/{no}` | 单票预演明细 |
| POST | `/admin/rebuild` | 全量重建（核对用，正常写入只走增量） |

### 抽检版

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/samples/months/{mon}/versions` | 按发车月开抽检版，返回版号与总行数 |
| GET | `/samples/months/{mon}/versions/latest` | 查该月当前有效版（无版 404） |
| GET | `/samples/versions/{id}` | 按版号查版信息（版不存在 404） |
| POST | `/samples/versions/{id}/lines` | 提交 ≤20 个行号，返回运单号/过磅记录号/价目记录号；越界 422 |
| GET | `/health` | 数据版本号与库路径 |

写入响应统一返回 `version / affected_waybills / affected_months`，可直接核对
增量范围。注意：**开版是只读冻结，不推进来源数据版本号**；版头里的
`source_version` 记录开版时冻结的是哪个已提交状态。

## 关键设计如何满足需求

1. **同一已提交状态开版**：删旧版、插新版头、冻结票统计与成员关系全在一个
   `BEGIN IMMEDIATE` 事务内；并发写者在锁外等待，拿到锁后才提交，不会混入
   开版快照（有并发线程实测）。
2. **失败保旧版、成功只留新版**：旧版删除与新版冻结同事务，任何错误整体
   回滚；成功后外键 `ON DELETE CASCADE` 清掉旧版全部冻结数据与已抽行。
3. **冻结的是“实际命中关系”而非当前来源**：成员关系由开版当时的两次内连接
   物化（`sample_waybill_weigh/price`），之后过磅改车次、价目改窗口、记录
   撤回都不影响旧版解析；来源内容表仅作去重存档，解析路径不依赖它。
4. **行号编号确定**：票间按运单号升序、票内按过磅号升序、同过磅下按价目号
   升序，与 SQL 两次内连接后 `ORDER BY 运单号, 过磅号, 价目号` 的次序一致，
   从 1 起算；漏配票（0 行）不占号但仍保留统计可解释。
5. **查一个行号读取 ≤ 32 票命中统计**：`sample_waybill_stats(version_id,
   cum_rows)` 索引点查，实测计划为 `SEARCH ... USING INDEX
   idx_sws_version_cum`，每个行号只读 **1 条**票统计。
6. **只生成抽中的计费行**：库中没有全量计费明细表，`sampled_billing_lines`
   仅在行号被查询时惰性写入，主键保证版内同一行号至多一份；冻结来源内容表
   主键 `(版号, 记录号)` 保证**版内每条来源记录最多存一份**。
7. **预演层增量重算**：来源写入前记录旧匹配条件，只重算涉及运单与月份；
   来源与 `match_stats` / `monthly_totals` 在同一事务原子提交。
8. **重启可复现**：冻结数据全部落盘在同一 SQLite 文件（compose 命名卷），
   重启后版号、行号解析与已抽行保持不变（有重启实测）。

## 实现状态

### 已实现

- 批量运单导入；过磅单/价目按记录号补录、替换、撤回；价目有效期含首尾两日。
- 每票两侧命中数、内连接行数、异常标记；按月合计；异常运单键集分页。
- 按发车月开抽检版：单事务冻结同一已提交状态，返回版号与总行数；每月一个
  active 版，失败保旧版、成功只留新版（级联清理）。
- 凭版号提交 ≤20 个行号反查三单号，三项升序从 1 编号，越界 422；只生成
  抽中的计费行，重查幂等，版内来源记录去重一份。
- 冻结实际命中成员关系 + 去重来源内容；来源改动与服务重启后旧版解析不变。
- `cum_rows` 索引点查，每号 1 条票统计（上限 32 票）；行号解析不回源。
- docker compose 一键启动、`/docs` 全接口可调、健康检查与持久化卷。

### 已验证

- 27 个 pytest 用例全部通过；真实 uvicorn 进程 HTTP 走查 100 票/200 行大版：
  边界行号、跨票编号、越界/超量/重复校验、来源更正后新旧两版行为、失败保旧版。
- 重启实测：停服再起后版信息与行号解析一致，旧版仍不可查、新版仍可查。
- 直连 SQLite 核对：只落 2 条抽中计费行、100 票共享价目只存 1 份、
  `EXPLAIN QUERY PLAN` 确认 cum_rows 索引点查、每月一个 active 版索引存在。
- 并发线程实测：开版持锁期间来源写入等待，开版冻结的是等待前已提交状态。

### 未完成 / 边界说明

- 本环境无 Docker 守护进程，compose 文件仅做 YAML 静态校验，未实际
  `docker compose up`（Dockerfile 基于 python:3.11-slim，步骤与本地验证过的
  安装/启动方式一致；`docker compose config` 可在有 Docker 的环境复核）。
- 未做认证/鉴权与多租户隔离，定位为内网抽检工具。
- 未实现运单本身的修改/删除接口（需求只要求一次导入）。
- 抽检版按月保留当前版；历史版在新版成功后即清理，不提供历史版归档查询。
- 金额未入抽检结果：价目表带 `price_per_t` 但行号只反查三张单据的记录号，
  不生成金额明细。
